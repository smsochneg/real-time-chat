# real-time-chat

## Real-time chat application

### Как запускать:

В корне

```
nvm use
npm run build
npm run start
```

Если у вас не MacOS то скорее всего упадет (из-за docker compose)

Тогда

```
docker-compose build
docker-compose up
```

Клиент будет на <http://localhost:5173>
Сервер будет на <http://localhost:3000>

---

### Технологии

MongoDb, NextJS \+ Mongoose, [Socket.io](http://Socket.io), Svelte@4, Skeleton UI \+ Tailwind

---

### Что сделано

Фронт:

- Обертки над fetch для клиента и сервиса с пробрасыванием куки и проверкой авторизации
- Проверка авторизации - если нет то редирект на /login
- Сообщения - при первом заходе в чат грузим все. При переключении между чатами - догружаем только новые
- Pending messages из ws (читай комент в сторе)
- Тостер из Skeleton UI для отображения ошибок

Бэк:

- `toJSONPlugin` для красивости документа (id вместо \_id)
- Websocket. При отправке - понятно что происходит. А при рассылке сообщения два способа. Первый как `chatsHandlers` - с пробрасывание ws client и server. Второй через `EventEmitter2` и перехватом в ws-gateway

Авторизация:

- JWT (без refresh токена)
- Сохранение токена в куки
- AuthGuard - проверка куки в HTTP запросе
- WsAuthGuard - проверка куки в WS (\+ проверка в handleConnection)

Пользователи:

- Логин, почта, пароль. Авторизация по почте и паролю
- Аватарки с какого-то сайта с моками (чисто для красоты)
- Пароль по дефолту выкидывается из документа (свойство в схеме)
- Поиск пользователя по логину (regexp в монго). SearchInput в чате отдаст 10 пользователей по подстроке

Сообщения:

- Создание сообщение через REST, рассылка события через WS

Чаты:

- Отображаются только те, в которых состоит пользователь
- Перед сохранением создание `usersHashKey` для предотвращения дупликации чатов
- Подключение к комнате через `client.room().join()`
- При создании - рассылка участникам через WS, событие чтобы отрисовать чат

Истории:

- Отображаются сразу для всех пользователей
- Можно через env переменную настраивать время удаления
- Для cleanup не TTL индекс, а cron, который пачками удаляет документы
